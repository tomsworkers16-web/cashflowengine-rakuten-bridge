# Magazine editorial pilot

ラクミツは読者価値を先に考える暮らしの読み物へ。記事企画→根拠調査→商品選定→執筆→校正→公開承認→評価を基本とする。第一版は3企画の固定編集原稿を短文・特集としてプレビューするのみ。商品検索・AIによる自由執筆・実際の投稿は未実装。通常投稿500文字以内。長文添付APIは公式確認後に別設計。既存投稿・設定・PR #99のOFF状態は変更しない。次は実際の候補商品の仕様を検証して記事に接続し、プレビューを確認してから運用承認を求める。

## 商品候補との接続

`previewMagazineWithProducts(day, slot, items)` は既存の楽天商品データ形式（itemCode, itemName, price, affiliateUrl）を受け取り、記事テーマと商品名の関連性を確認する。候補がない場合は非商用記事をそのまま残す。候補があっても仕様・価格・送料は別途確認が必要。広告原稿はレビュー専用、PR表記・500文字制限・元リンク保持を検査する。実際の楽天API取得処理への接続、仕様の検証、自由執筆、自動公開は未実装。

## 楽天検索プレビュー

`node --env-file=.env src/preview-magazine-research.js 2026-11-11` で記事企画のキーワードを一回だけ楽天APIへ渡し、関連候補と記事プレビューを表示する。429は再試行せず終了。資格情報やリクエストURLはエラー出力しない。実APIの動作確認はM8で実施する。自動投稿には未接続。

## 収益機会発掘（2026-11-11）

`node --env-file=.env src/preview-magazine-opportunities.js 2026-11-11` は既存の3企画に対応する楽天検索をすべて実行し、記事と関連する商品候補をレビュー数・評価・取得できる報酬率・関連商品数・履歴の重複で暫定評価する。最上位の候補を選び、執筆指示に渡す。実売上・需要予測・利益の推定ではない。報酬は掲載価格×取得された料率の概算（上限・成果条件・取消等未反映）。不明な指標はnull。候補がない場合は商用企画を選ばない。検索失敗時は途中結果で選定せず終了し、429の再試行なし。現在は3テーマ限定で、季節需要、ランキング、SNSトレンド、実績CVとの統合は未実装。プレビュー専用で公開なし。
