# Threads投稿の導入文と投稿枠の観測診断

目的：楽天の商品探索よりも「表示数が足りない」という現時点のボトルネックを優先する。

- 過去7日の投稿台帳を投稿枠単位の最新状態で集計し、投稿日時枠（07:30/12:30/19:30等）、役割（ガイド/収益等）、冒頭文の型を区分。
- 夜間レポートに保存済みの投稿別表示回数を結合（累計表示回数の観測最大値）。未取得は `unknown`、非公開・不明な投稿は成功に含めない。
- 結果に投稿本文・URL・秘密情報は含まれない。ユーザーが端末で実行した時のみローカルで読み取る。
- `averageLifetimeViewsObserved` は期間内表示数ではなく、投稿時刻・経過日数による条件も統一されていない。各グループの表示観測が5件未満なら `comparisonReady=false`。表示数の差が投稿文によると断定せず、自動勝者選定や自動投稿変更はしない。
- 操作：mainへ統合・M8最新版取得の承認後、`m8-agent-node` 内で `npm.cmd run threads-hook-diagnostics`。
- 楽天側のクリック0件（報告済み5日間）と収益投稿の累計35表示（5投稿）は前提として分析するが、このコマンドはThreads指標と楽天成果を無理に帰属させない。

2026-11-10 ではPRでテストのみ。main統合／M8への展開／投稿の変更は別途オーナー承認が必要。
