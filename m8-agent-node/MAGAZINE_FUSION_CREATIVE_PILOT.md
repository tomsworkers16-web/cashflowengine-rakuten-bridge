# 融合方式のA/B原稿パイロット（非公開）

## 目的
ネット上の記事・口コミで見つけた読者ニーズを記事の切り口に取り込んだときに、既存方式よりも表示・クリック・成約・利益が改善するかを将来検証する。既存の投稿システム、main、M8常時運転設定には変更を加えない。

## 実装した比較
- baseline: 楽天商品データを使った一般的な選び方。
- fusion: 確認された外部情報源の「調理スペースに困っている」という課題から始める。
- **同じ商品コードとアフィリエイトURL**を両腕で使う。商品選定改善とコピー改善の効果を混同しない。
- 元の検索結果から違う商品が選ばれた場合はA/B原稿を作らず、別の「選定方式の比較」として扱う。
- 外部証拠は別ドメイン2件以上必要。情報源は需要や売上を証明しない。
- 本文は実商品情報に照らして公開前に事実・適合条件を確認する。
- 500文字、PR表記、アフィリエイトURL非改変の検査を通した後も `publicationAllowed=false`。
- 企画・原稿は**固定のパイロット**であり生成AI自動執筆や投稿配信は未接続。

## 実験の実施条件
1. 投稿予定日・同一時間帯・実験方式を**結果を見る前**に固定する。
2. 原稿の違い以外の条件をなるべくそろえる。同一日の重複露出や順序の影響を考慮する。
3. 楽天の投稿別計測ができない場合、販売成果の投稿別勝敗は不明。リンクCTRはプラットフォームで実測できた場合のみ示す。
4. まず少数の投稿で安全・リーチを観察、実験が成立するデータ量がなければ利益比較は保留。
5. 本番公開・本番スケジュール変更・main統合はオーナー事前承認。

## 現在の限界
- 外部情報収集はまだ半自動の資料登録。記事の存在を需要の強さと解釈しない。
- 原稿はユーザー向けの仮説であり、読者がクリックするかは未計測。
- 記事の引用・コピーはしない。
