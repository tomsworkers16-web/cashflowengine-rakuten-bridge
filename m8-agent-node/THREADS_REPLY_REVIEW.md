# ラクミツ返信運用（開発版）

- いいね・フォローには自動返信しない。既存のインサイト集計を用いる。個別のいいね通知の取得は未実装。
- 自分の投稿と自分の返信についた最新コメントは公式APIのconversationから、直接の親投稿が自分であることを照合する。非表示、既返信、48時間超、取得不完全なスレッドを除外する。
- 質問・商品条件・苦情等は保留。返信候補は自然な標準語、リンク・営業誘導なし。現段階は限定的なルールベース下書きであり、文脈の深い個別回答はレビューが必要。
- 親投稿（再返信では元投稿も参照）の主題を先に特定し、コメントの意図と照合する。「片付け」という単語だけで収納へ誘導しない。時短グッズの片付け負担、掃除道具の後片付け、収納の出し入れ等は別の返信案とする。主題不明・質問・反論・皮肉・不一致は保留。現段階は外部LLM未接続であり、自由な会話生成ではない。承認ダイジェストには元投稿・親投稿・コメント・返信案を含める。
- `node --env-file=.env src/review-inbound-replies.js` は読み取り専用。候補の本文・親投稿・下書き・ダイジェストを表示する。Tokenや生APIエラーを表示しない。
- 明示的に承認された1件についてのみ、`node --env-file=.env src/review-inbound-replies.js --send-approved <digest>` を実行できる。再取得時に内容が変われば保留。JST 1日1件、送信意図を事前記録、確認不能なら再送禁止。
- 外部投稿の候補には `node --env-file=.env src/review-external-reply.js` を使用。承認記録は現時点では送信処理に接続されていない。

## 外部投稿の公式APIレビュー（個別承認）

`node --env-file=.env src/review-external-official.js` は当日のテーマで公式APIを1回検索し、明確に助言を求める投稿に限り、具体的な返信案を最大1件表示する。フォロワー数や広告効果は選定条件にしない。リンク・営業誘導・未確認商品・無関係な話題は除外。候補の本文と返信案を確認し、個別承認された場合だけ `node --env-file=.env src/review-external-official.js --send-approved <digest>` で1件を送信可能。再取得で本文や対象が変われば保留、日次上限と既返信・既試行の記録を厳守する。公式APIの検索・投稿取得・返信権限が不足する場合は停止し、代替の非公式操作はしない。定期的な無承認送信は行わない。既存の自己投稿／受信コメント限定の自動返信とは独立。
- 公式APIを使う受信返信機能の権限（threads_read_replies, threads_manage_replies等）と実際の見え方はM8で検証する。本番有効化・定期送信は未実施。既存自己投稿は変更しない。

## 受信コメントの定期監視

統合・導入後、M8で `node --env-file=.env src/enable-inbound-monitor.js` を一度実行する。既存コアの稼働とアカウントを確認して、公式APIの読み取り専用監視を有効化する。30分間隔の取得で `.data/inbound-reply-review.json` に候補と保留を記録し、`/health` に件数・最終取得時刻を表示。候補0件は正常。監視自体には公開処理がなく、自動送信は無効。1件の実送信はオーナーによる対象本文確認・承認後に既存の限定送信手順で検証する。

## 受信限定の自動返信（初期無効）

実送信の確認済み記録があり、オーナーが明示的に運用を承認した場合のみ、`node --env-file=.env src/enable-inbound-auto.js --enable` で有効化する。自分の投稿・返信に直接届いた新着コメントに限定し、開始以前のコメント、質問・苦情・不明な文脈は対象外。1日1件、公式APIの再取得・重複防止・公開確認を必須とし、送信結果不明時は再送しない。外部投稿への能動的返信、いいね、フォロー、DMは対象外。停止は `node --env-file=.env src/enable-inbound-auto.js --pause`。有効化コマンド自体は投稿を行わない。
