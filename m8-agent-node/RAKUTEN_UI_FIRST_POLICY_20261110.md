# 楽天成果取得の運用判断（2026-11-10）

## 結論
当面、検証済みの楽天管理画面「日別」の表示行を主要な取得経路とする。CSVの日付欄不正が解消するまで、自動CSVエクスポートの定期的な再試行を行わない。

- 2026-11-10 の M8 `revenue-status`: 4件の拒否CSVはすべて日付欄のプレースホルダーが不正、内容は実質1種類。原因は未確定。URLに `monthly` が含まれることだけでは誤ダウンロードと断定できない。
- 楽天管理画面の日別行からの代替取り込み `ui_daily_fallback_imported` は確認済み。7日間のうち5日分の報告があるが、未報告の2日間を売上0と推定してはいけない。
- 修正は夜間収集で既に有効なUI代替実績がある場合、以降の夜間実行を `ui_daily` に固定する。既に日付不正CSVと判明した場合も次回からUI取得へ移行する。毎日1回の実行・ロック・状態チェックは維持。
- 意図的に `RAKUTEN_CSV` の原本、拒否ファイル、過去台帳を削除しない。UI由来のデータが確認済みの独立したCSV記録を上書きしない既存保護を維持。
- ただしUIへのログイン切れ、ページ構造変更、画面表示の遅延は別途検出する。UIの未検証結果を成功と報告しない。
- 自動投稿スケジュール、Threads投稿、外部返信、画像利用、予算は一切変更しない。

## 作業範囲・運用
- この変更は作業ブランチとPRまで。main統合とM8実運用への反映はオーナー承認が必要。
- 夜間の自動取得でのUI優先は、3日おきの再失敗CSVを防ぐ措置。CSVそのものの根本原因が修復されたことを意味しない。
- 既存Issue #91でCSVの根本原因を独立管理し、集客・初収益改善とは切り離して扱う。

## 合格条件
- 実際にUIフォールバック取得済みのM8で、最新版反映後に夜間CSVを再取得しない。
- 自動テストで6日連続UI取得、既存UI状態からの移行、日付不正CSVからの移行、同日多重取得禁止、機密情報非出力を検証。
- M8反映前のCI合格だけでは本番動作が正常とは報告しない。
