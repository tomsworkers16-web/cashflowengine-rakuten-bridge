# 雑誌型メディア融合実験：測定計画（非公開・read-only）

## 実装
- `src/magazine-fusion-experiment.js`：各投稿に明示された腕（baseline/fusion）を照合し、既存のThreads日次スナップショットから投稿年齢18〜42時間の表示数を集約。
- `src/report-magazine-fusion-experiment.js`：既存 `posts.jsonl` と `reports/*-night.json`、独立した割当JSONを読み込み、投稿はせずにレポート表示。
- 割当は**投稿前に確定**する。結果を見てから腕を付け替えない。投稿IDを付けたJSONは実験台帳であり、商品スナップショットとは別。
- 投稿IDをThreads上で取得できた場合にのみ台帳に追加。重複IDや未知の腕を拒否。
- 基準の表示比較は**同一時間帯で**行い、両腕5件以上の観測がない限り比較準備完了としない。
- 5件は最低データ量の目安であり、統計的有意性や因果推論を保証しない。
- 投稿日時と計測タイミングは完全一致しないため、実際の年齢差、題材、フォロワー、季節、投稿順序などを確認する。
- クリック・成約・報酬・利益は楽天側の**投稿別帰属**が立証できる場合のみ投稿別指標とする。現時点の楽天日次レポートだけでは不可能。値を0で補完しない。
- `winner=undetermined` を固定し、本人承認なしで勝者切替・自動投稿・広告配信しない。

## 割当JSON例（仮データ・実際の成果ではない）
```json
[
 {"postId":"18224593717352322","jstDate":"2026-11-05","slot":"19:30","arm":"baseline","itemCode":"shop:123","topicId":"kitchen-cleanup"}
]
```
**注意：上の例は架空の実験割当であり、その投稿に実験区分・商品を裏付けるものではない。実運用でコピーしないこと。**

## M8でのオフラインレポート
```powershell
node src/report-magazine-fusion-experiment.js "既存dataDir" "承認済み割当JSON" "YYYY-MM-DD"
```
割当ファイルがなければ実験は始まっておらず、実績比較は行えない。

## 本番試験で必要な追加準備
1. 同じ商品と価格帯・投稿時間の偏りを減らして企画を用意。記事の切り口による違いと商品選定による違いを区別。
2. 事前にbaselineとfusionの投稿割当を固定し、実際の投稿IDと対応づける。
3. クリックと楽天成果の追跡可能範囲を確認し、投稿別帰属が無理な場合は比較を表示回数とアカウント単位収益の記述に限定。
4. 投稿・main統合・本番設定変更はオーナーの事前承認を得る。既存autoPost設定は維持。
