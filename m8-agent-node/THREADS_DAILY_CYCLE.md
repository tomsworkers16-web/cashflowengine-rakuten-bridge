# Threads daily editorial cycle (development, opt-in)

The existing three JST slots become one coherent daily theme: 07:30 reader-first column, 12:30 selection checklist/comparison, 19:30 related PR. The PR preserves the official affiliate URL exactly. No isolated PR fallback. The daily commander builds a proposal from official Rakuten discovery and bounded detail/page research; the selection uses available audited item performance and excludes recently featured products. Missing evidence holds the cycle. Night evaluation records confirmed stages and measured per-post views by ID; missing data and campaign-level affiliate attribution stay unknown.

`CFE_THREADS_DAILY_CYCLE_ENABLED=true` opts in; default off. Existing auto-post and reply settings remain separate. The new mode requires explicit review of the immutable daily proposal. Review locally from the agent directory with `node --env-file=.env src/review-threads-daily-cycle.js`; owner approval of the exact digest uses `node --env-file=.env src/review-threads-daily-cycle.js --approve <digest>`. This command does not publish or approve external replies. Replies require a separately reviewed exact URL list in the approval document, unchanged source/draft, confirmed morning stage, existing reply enable flag and daily limit of three. Missing approvals hold. No catch-up or uncertain retry; earlier stages must be officially confirmed before progression. No automatic new tracking ID generation or invented attribution.

No production configuration, owner approval, live publication or real Rakuten/Threads experiment is performed by these development changes. M8 installation, existing task compatibility, real product evidence, and live end-to-end verification are still required. This cycle does not implement note/ROOM features, image publishing, or automatic approval of future content.

Tests: `node --test test/threads-daily-cycle.test.js test/threads-daily-preparation.test.js` (mocked APIs, no live calls).
