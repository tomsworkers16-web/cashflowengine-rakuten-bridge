# Threads 投稿の公開後ほぼ24時間に揃えた表示比較（調査専用）

現状、収益投稿5件の「観測できた累計表示数合計35」という実績は、古い投稿ほど観測時間が長く、そのまま良し悪しを比較できない。

この分析では保存済み `posts.jsonl` の公開時刻 `at` と、毎晩の `reports/YYYY-MM-DD-night.json` の `generatedAt` と投稿別 `views` の記録を使う。公開後18〜42時間にある観測だけから、**24時間に最も近い1つ**を選ぶ。該当する記録がなければ `unknown` とし、0とはしない。

```powershell
npm.cmd run threads-age-matched
```

- 投稿IDごとに24時間に近い観測値（朝投稿は翌夜に約40時間後）と実際の経過時間、導入文型、投稿枠、投稿役割を一覧化。原文やアフィリエイトURLは含めない。
- 観測できた投稿が各グループ5件未満なら `comparisonReady=false`。勝ちパターン自動決定はしない。
- 18〜42時間は厳密な24時間同一条件ではない。比較は同一投稿枠内に限定し、実測経過時間も確認する。時刻やフォロワー、投稿内容、外部配信の違いによる偏りは残る。
- 投稿、Threads API接続、CSV再取得、台帳書込、設定変更は行わない。
- 2026-11-10時点では開発ブランチのCIまで。main統合、M8反映は別途承認が必要。

次の実行時に実測の欠落が多ければ、夜間レポートの測定時刻・投稿選択の見直しを検討する。投稿数を増やす前に、既存の1日3投稿で比較できる測定データを蓄積する。

## 2026-11-10 実測後の修正
18投稿中、旧条件で比較可能だったのは4投稿（収益投稿のみ）。夜間評価は既存の1回・最大8投稿のAPI呼び出し枠を維持し、前日全投稿→当日全投稿→それ以前の収益投稿の順で計測する。朝・昼・夜を翌夜のスナップショットに含めるため上限を42時間に変更し、異なる投稿枠を同一条件と扱わない。過去の未取得値は復元できない。楽天レポート取得・投稿数・投稿時間は変更しない。
