# Cash Flow Engine #001: 外部需要シグナル × 楽天商品評価（融合パイロット）

## 目的・安全境界
楽天商品検索・季節要因・回転型／報酬重視型の評価を維持し、ネット記事／SNS／検索トレンド／口コミで発見した読者の悩みを、**別の証拠レイヤー**として重ねる。
ネット記事は需要・販売を証明しない。原文の転載、未承認のスクレイピング、アクセス制限回避、他人の体験の捏造は禁止。
既存の基準スコアやselectedを変更しない。融合結果は `fusion.selected` に分離し、従来と同じスナップショットで比較可能にする。投稿・本番設定・API呼び出しなし。

## 受け入れ形式（配列JSON）
各レコード:
- `topicId`: kitchen-cleanup / storage-flow / washbasin / winter-warmth / winter-cleaning
- `sourceType`: article / social / search_trend / review
- `url`: 公開ページの追跡パラメータなし HTTPS URL
- `observedAt`: 検証・観測日時 ISO8601（過去90日以内、未来不可）
- `title`: 出典を識別する短い見出し
- `readerNeed`: その情報から抽出した読者の悩み（要人手／AI確認）

著作物本文、個人を特定できるSNSユーザー情報、広告ID、APIキー等は保存しない。入力内容は検証済みの事実とは扱わない。URLの有効性や本文をHTTP確認する機能ではない。発見した記事の利用許諾と公開可否は別途確認する。

## 重複・鮮度とスコア
- 90日超、未来日時、未知topic/type、重複した同一ドメイン＋URL、クエリ付きURL、HTTP URLを採用しない。
- 記事・SNSなど異なるソース種類、独立ドメインによる相互裏付けを最大+10点で暫定評価。同じドメインの記事量は需要として加点しない。
- 実測表示回数、CTR、CVR、確定報酬、利益、トレンド増減を**推定しない**。
- **暫定5ジャンルのみ**に紐付け可能。新たに未知ジャンルを発見して楽天検索する機能は未実装。
- レポートのランキングの違いは評価式の差であり、A/B投稿実績ではない。

## M8の非公開オフライン検証
1. `m8-agent-node/test/magazine-demand-evidence.test.js` を含む magazine テスト群を実行する。
2. 証拠データが未準備でも既存スナップショットだけでA/Bの基準一致を確認可能。
3. `node src/preview-magazine-demand-fusion.js "<商品スナップショット>" "<証拠配列JSON>"` を実行。証拠ファイルを省けば外部証拠0件の基準比較になる。ファイルは個別の承認済みデータのみ。
4. ネット検索・SNS巡回は実行しない。実運用での収集元・頻度・利用規約・コスト・収集情報の最小化は別途設計。
