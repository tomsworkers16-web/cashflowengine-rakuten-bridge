# Cash Flow Engine：公開JSON Feedからの記事候補収集（第1段階）

## 概要
既存の商品候補スコアは維持し、**読者の疑問を探るための素材となる記事見出し**を自動的に取り込むためのオプトイン機能。2026-11-15時点で初期実装。現段階で対応するのは JSON Feed v1/v1.1 のみで、一般的なRSS/Atom XMLは**未対応**。SNS、口コミ、検索トレンドの自動収集も未実装。

`src/magazine-json-feed-demand.js`:
- 登録した最大5件の許可済みHTTPSフィードのみを取得。未設定ならネット通信なし。
- リダイレクト禁止、8秒タイムアウト、最大256KB、各フィード最大30件、フィード元と異なるドメインの投稿URLは不採用。
- 見出しを既存の5つの編集ジャンルへ**単一分類できた場合だけ**候補として採用する。
- 記事本文・HTML本文・著作権対象の文章、個人情報、検索追跡パラメータを保存しない。
- 取り込んだ日付は`observedAt`であり記事の公開日やトレンド発生日ではない。
- 記事の見出しは**ニーズの仮説**にすぎず、検索数・売上・成約の裏付けではない。 `readerNeed` も確認を促す仮文であり、裏付け済みの購買動機ではない。
- 既存 `normalizeDemandSignals` を通し、鮮度・URL・ドメイン重複などをチェック。データの無条件採用はしない。
- 非公開・投稿機能なし。GitHub main、M8の予約投稿、外部APIキーには変更なし。

## 設定形式（この内容はサンプル。架空の接続先であり実際に実行しない）
```json
{
  "feeds": [
    {"enabled": true, "url": "https://example.org/feed.json", "allowedDomain": "example.org"}
  ]
}
```
実利用では、公開かつ取得が許容されるJSON Feed URLを別途確認して設定する。明示的な承認なしにサイトを横断取得しない。サイトの利用規約・再利用条件も確認する。

## ローカルプレビュー例
```powershell
node src/preview-magazine-json-feeds.js ".\\private-approved-feeds.json" "2026-11-15"
```
結果の`signals`を需要評価エンジンの `demandSignals` として渡せる。利用規約を確認する前に定期取得へ設定しない。現在は「フィード→出典メタデータ」の独立機能であり、M8の既存の無人投稿フローへは接続していない。

## 限界と次の段階
1. 実在する配信元を調査し、利用条件・形式と記事の取得可否を確認する。
2. RSS/Atomに対応し、サイトへ負荷をかけない最小間隔・障害時の停止を整備する。
3. 実データで誤分類・重複・記事品質の検証を行い、固定ジャンル以外の新しい需要にも対応させる。
4. ネット記事の全文再利用・誇大表現を防ぎつつ、AIライターへ出典と記事要点を渡す。AI接続は別途検証。
5. 最終的には同じThreads投稿枠で実績比較を行い、**確定利益**で判断する。

## 楽天評価との統合プレビュー
`src/preview-magazine-feed-fusion.js` により、**当日取得した楽天商品スナップショット**と、許可済みJSON Feedから取得する記事候補を同一のオフライン比較レポートで評価できる。

```powershell
node src/preview-magazine-feed-fusion.js "当日の商品スナップショット.json" "承認済みのfeed設定.json"
```
- `baseline` と `fusion` の選定topicId、itemCode、元スコア、融合スコアを個別表示。
- 結果は投稿せず、価格・リンク・収益は報告しない。
- 過去に保存した商品スナップショットと、後日取得した記事を組み合わせると、過去の実験評価に未来の情報が混入する。このため**日付が一致しない場合は一切外部取得せず `snapshot_stale_for_live_evidence` で停止**する。
- 2026-11-11の既存スナップショットは現在のフィード取得との統合には使えない。M8側で当日取得したものが必要。
- 利用許諾を確認していない情報源や購買需要の未確認の主張は自動投稿判断には使わない。
