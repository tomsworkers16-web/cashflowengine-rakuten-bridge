# スマホから実装まで — 運用手順（暫定版）
2026-11-22

## 目的
ユーザーはスマホ/メインPCから自然文でアイデアを伝える。ChatGPTが可能な限り質問を省き、GitHubの承認済み開発ブランチに実装し、M8の隔離環境にテスト依頼する。

## 現在の実装範囲
- **実施済み**: 非公開GitHubリポジトリ `tomsworkers16-web/cfe-m8-control` にアイデアIssue #20を作成。これにはM8実行ラベルを付けていない。
- **実施済み**: 開発用の入力テンプレートと本手順書を作成。
- **実施済み（既存）**: `editorial-sync-test` で開発ブランチ取得・隔離環境テスト76/76、exitCode=0、GitHub返信（Issue #18）。
- **未実装**: 新しいアイデアをChatGPT外で自動的に検出してコードを書き続ける自律開発エージェント。GitHub Issueが勝手にコード化されるわけではない。

## ChatGPTの通常手順
1. 自然文のアイデアを理解し、事業利益・期限・既存サービスへの影響で優先順位を決める。危険な不可逆操作以外は質問せず進む。
2. `docs/IDEA_INTAKE_TEMPLATE_JA.md` を使い、まず **非公開Issue** を作成。タイトルは `[IDEA-NNN]`。秘密は書かない。M8指示用ラベルは絶対に付けない。
3. 仕様正本・テスト・コードを読み、**作業ブランチのみ**編集。mainは変更しない。
4. 可能な範囲でテスト実行。M8上の既存隔離コードを使う必要がある場合、非公開制御リポジトリに **別のIssue** を作り、タイトルは `[M8-REMOTE]`、本文は許可済みコマンド `editorial-sync-test` 等のみ、`m8-remote` ラベルを付ける。
5. テストの閉鎖・結果コメントを確認してから成功を報告。「Issue登録」と「実装完了」を区別する。
6. 開発成果が揃ったら公開・本番反映・mainマージに関するオーナー承認を確認する。
7. 収益化後はクリック・CV・報酬・実利益・サポート工数で評価。未計測なら推測と表示。

## 優先順位
- P0：売上・利益に直結する問題、安全上の欠陥、開発を止めている障害。
- P1：小さく実装できて繰り返し使える仕組み、投稿記事の成約率改善。
- P2：開発コストが高く効果が不明な仕組み、装飾や過剰な自動化。
- 今回の最小実証では1件ずつ検証し、拡大は実測後に判断。

## スマホでの入力例（ユーザーは形式を覚える必要なし）
「ラクミツで、比較表がある記事の方が購入される気がする。安全にテストできる範囲で機能を作って」
→ AIは効果を断定せず、記事の比較表の受入基準・検証指標を作成し、実装・テストへ進める。

## 非常時
- M8健康確認: 非公開リポジトリに `[M8-REMOTE]` / `health` / `m8-remote` Issueを作り、自動返信を確認。
- 未検証の「本番で動く」「実運用の増益」は報告しない。
- M8ブリッジのPowerShellはコマンド自由実行を許可しない。現在のホワイトリストを維持。
