## 自律開発エージェント
- **実機で成功済み**：非公開Issue → owner検証 → 隔離Gitブランチ → Codexコード生成 → 対象テスト → 成果物を非公開Issueで回収 → 人がレビュー → 開発ブランチへ反映 → M8回帰テスト。IDEA-003 / Issue #30・#32。
- **今回実装**：`ops/idea-agent/auto-queue.mjs` に明示 `[AUTO-IDEA]` の1件選定・優先度・開始/完了/保留マーカー・重複回避。 `one-job-orchestrator.mjs` に開始記録→作業準備→実行→レビュー提出→完了/保留の統合処理（依存注入・実行器モックによるテスト）。25件のテストを追加、M8 Issue #35 **143/143合格**。

- 既存のWindowsユーザーには本番プログラムやDPAPI資格情報が存在する。**同じユーザーでCodexを無人実行してはならない**。専用Windowsユーザー/VM等でソース・Secrets・本番フォルダへのアクセスを遮断し、認証・権限を実測するまで適用しない。少なくともこの段階で本番タスク登録はしない。

## Cash Flow Engine本体
- 実績のない楽天ランキング上位商品に偏らないよう、`src/editorial-performance-priority.js` を実装。
- `records` には楽天等の**出典と一意なrecordIdがある**実測データを使い、重複取込を防止。クリック・注文・確定報酬・費用が揃わない場合は`unknown`相当、仮報酬は確定利益に計上しない。最少クリック未達はサンプル不足。記事や投稿単位への売上帰属は証拠なしには主張しない。
- `src/run-editorial-performance-priority.js` を追加。 `npm run editorial-performance -- <input.json>` でローカルレポートから調査優先度を計算可能。**SNS投稿や販売行為は行わない**。
- 隔離テスト Issue #36：記事関連・無人キューの合計 **152/152件合格**、exitCode 0、published=0（対象commit `249e68b10ea2ffe8ef88be1e95983454e524afb7`）。その後CLIとpackageコマンドを追加したため最新版全件再テストは別途必要。
- **次の本題**：実際のRakuten報告データから利用可能な `recordId`・`rewardStatus`・`costYen` が揃うか監査し、商品別に実測がある範囲で研究優先順位を運用。自動投稿の拡大は効果検証・オーナー承認後。
