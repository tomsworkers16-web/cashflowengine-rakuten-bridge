# アイデア → 実装までの高速運用モデル（案）
作成日: 2026-11-22 / Cash Flow Engine検証

## 最重要方針
オーナーがうどん店営業中・スマートフォンからでも、アイデアを自然文で送れば、AIが仕様確定可能な部分を判断し、作業ブランチで設計・コード変更・検証を進める。オーナーの操作を承認と例外判断に集約する。PC所在地やユーザーの応答待ちを理由に不要な中断をしない。

先行者利益が残る期間は不確実。「半年〜1年」はオーナーの戦略仮説であり予測として断定しない。最優先は初収益までの時間、実利益、検証回数。

## 運用経路
スマホ/PCからのアイデア
→ AIが事業価値・最小成功条件・禁止操作を分類
→ GitHub Issue（アイデアの正本、受入基準と優先順位）
→ 作業ブランチの実装
→ 自動CI / M8隔離テスト（現行の非公開GitHub Issuesブリッジを再利用）
→ AIが合否・差分・リスクを報告
→ （必要時のみ）オーナー承認
→ 本番適用・効果計測
→ 改善・継続/撤退判断。

### 実行の3区分
A. 自動で進める: 情報整理、技術調査、設計、作業ブランチへのコード変更、単体テスト、隔離環境へのコード取得・テスト、ログの安全な集計。
B. オーナー承認待ち: mainへのマージ、公開、決済、課金、顧客への送信、実SNS投稿、既存本番環境の変更。
C. 本人作業が必要: サービスのアカウント作成・本人確認・機密入力・端末初回認証等。

### スマホ入力の扱い
自然文だけで受け付ける（専用フォームを強制しない）。複雑なアイデアもAI側でタイトル、課題、最小機能、受入基準、優先度に整形。足りない重要情報がある場合に限り1つずつ質問。未回答でも安全な作業範囲は進める。

### タスク状態
Inbox → Triaged → Scoped → Coding → Testing → Review → AwaitingApproval → Shipped → Measuring → Iterate/Stop。
各Issueには成果物・次のアクション・検証結果・未確認事項を記録。GitHubを正本としチャット記憶だけに依存しない。

### 実現段階
1. **すぐ**: ユーザーがこのChatGPTへアイデア送信 → その会話中にGitHub Issueと作業ブランチ作成・コード修正・M8隔離テストまで実行。ユーザーがその時に端末を触れる必要はない。ただしChatGPTの単発会話は自動継続保証なし。
2. **次**: 非公開GitHubのIssueを自律実行エージェントが監視し、承認不要範囲を継続処理。自動実行は常時動く専用ランナー、資格情報、実行権限の限定、ジョブ排他・期限・監査ログを別途構築・検証する。ユーザーのチャットを離れた後もChatGPT自体が勝手に作業するとは扱わない。
3. **後**: 複数案件の優先順位付け、性能/採算KPIでの自動改善、ロールバック・撤退判断の高度化。

## 過剰設計を防ぐ
- 最初の対象はCash Flow Engine 1案件、Issue 1件ずつ。
- アカウント/サーバ権限の拡大や無制限コマンド実行を避ける。
- 1機能は小さく実装して検証し、ユーザーに再説明を求めない。
- 収益化（クリック→成約→利益）の検証を技術基盤構築より優先。
- 本番自動実行、公開、mainへの変更は必ず事前承認。

## 2026-11-22 決定：開発中の逐次確認を省略
オーナー指示：「毎回確認する作業を省略したい。確認があると作業が止まる」。

- **既定動作**：AIは調査→仕様整理→GitHub Issue→作業ブランチ実装→コミット→隔離テスト→不具合修正→再テスト→レビュー準備まで、都度の続行確認なしに連続実施。回答時に「進めますか？」と質問せず、実行できる作業は当該ターン内で進める。
- ユーザーへの途中報告は状態共有であり、返信待ちの停止点ではない。失敗時も安全な範囲で修正・再検証を継続する。
- **承認が必要な境界は維持**：mainマージ、既存本番の変更、公開/SNS投稿、顧客への送信、契約・課金・決済、アクセス権限の大幅な拡張、秘密の外部送信や不可逆操作。これらを一括の曖昧な承認で自動実行しない。
- 自動作業の範囲が終わったとき、承認を必要とする境界に到達したとき、もしくは技術的に次へ進めないときに、成果と次の意思決定事項を一度で報告。
- 会話終了後に実装を継続することは、常駐型自律開発エージェントの実装・検証前には保証できない。その点を明確にする。
