# M8 自律開発用 Windows 実行ユーザーの分離 — 導入判定（2026-11-22）

## 事実
現行ログオン `NUCBOX_M8\\AI-FACTORY-NODE01` は管理者権限なしだが、診断v1で本番作業フォルダ・M8Remoteブリッジ・現在のWindowsプロファイル内のGitHubトークンへのアクセスを観測した。`accessible` は`Get-Item`が通ったことを示すだけで、実ファイル内容の読取可否を完全証明しない。ただし現行アカウントと本番プログラムが同居しているため、現行ユーザーでの無人Codexを承認しない。

## 採用方針
1. M8に**専用のローカル標準ユーザー**を作成する（予定名 `AF-CodexWorker`、管理者不可）。新規アカウント作成・権限変更はオーナー承認後にのみ実施。
2. CodexのChatGPTログインは専用ユーザーで実施する（ログイン資格情報をIssueやチャットに貼らない）。GitHubのPATはCodexプロセスに渡さない。
3. ソースへのアクセスは隔離された作業ルートのみ、リポジトリ・ブランチ・変更パスの登録制にする。
4. 本番 `C:\AI-Factory\cashflowengine-rakuten-bridge\m8-agent-node`、M8遠隔ブリッジ `C:\AI-Factory\M8Remote`、元ユーザーのWindowsプロファイル・DPAPIトークンへのファイル読取をACLまたはOS仮想化で禁止し**実際に否定的に検証**。
5. 権限分離が難しい場合は同一Windows上の無人Codex稼働を断念し、別VMまたは別コンピューターへ切り替える。アプリの`--sandbox workspace-write`だけをOS隔離の代替とはみなさない。
6. チャットからの一回実行と無人タスクスケジュールは別の承認境界。本番タスクの変更・新規常駐は未承認・未実施。

## 検証手順
- 開発ブランチの `m8-agent-node/ops/idea-agent/m8-worker-boundary-audit-v2.ps1` は、対象ファイルを**読み込まず開けるか**とディレクトリ一覧可否を確認する。利用者名と許可/拒否結果だけを出力する。
- 認証トークンや本番ファイルを開けるだけでなく、**専用ユーザーが他ユーザーのプロファイルや本番を読めないこと**をファイルACLの観察と実ファイルのOpen試験で確認する。
- ログイン済みChatGPT認証の再設定、無人ログイン、タスク再起動後の復旧は未検証。
- 診断は独立セキュリティ監査ではない。`isolationVerified=false`と表示して安全性を過大報告しない。

## 次の承認境界
オーナーに「M8にCodex専用のローカル標準ユーザーを新規作成し、本番/機密パスからアクセス分離する設定」を承認いただいた後、画面操作に沿った最小手順を提示する。既存ユーザーや本番ディレクトリのACLを変更する前に対象と影響を明示する。
